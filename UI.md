# Откуда берутся иконки в Qt UI и как добавить новую

Этот файл описывает, как устроены иконки в `src/ui/qt/icons.cpp` (composer, поиск, вложения и так далее): откуда взяты картинки, как они попадают в сборку, как перекрашиваются под тему в рантайме, и как повторить весь процесс руками, без участия ИИ.

## Коротко о принципе

Иконки не рисуются вручную кодом (никаких `QPainterPath` с координатами "на глаз"). Вместо этого используются настоящие PNG-файлы из официального клиента Telegram Desktop (`telegram_fork/tdesktop`), встроенные в сборку через Qt resource-систему, и перекрашиваемые под текущую тему в момент отрисовки.

Тот же принцип, что использует сам tdesktop: `style::internal::MonoIcon` (`telegram_fork/tdesktop/Telegram/lib_ui/ui/style/style_core_icon.cpp`) хранит белую картинку на прозрачном фоне и красит её под текущий цвет палитры при показе, а не хранит уже готовую цветную картинку под каждую тему отдельно.

## Откуда взять исходный PNG

Официальный клиент уже склонирован локально: `telegram_fork/tdesktop` (см. `CLAUDE.md` в корне репозитория про то, почему это gitignored и как устроено). Все иконки лежат в одном месте:

```
telegram_fork/tdesktop/Telegram/Resources/icons/
```

Файлы называются по смыслу иконки и приходят в трёх масштабах: `name.png` (1x), `name@2x.png`, `name@3x.png`. Для встраивания в zkgram нужен самый крупный вариант, `@3x`, — Qt сам уменьшит его при показе, а увеличивать маленькую картинку до нужного размера смысла нет, будет размыто.

### Как найти нужную иконку, если не знаешь точное имя файла

Есть два способа.

**Способ 1: искать по смыслу в файлах стилей.** Все элементы интерфейса tdesktop (кнопки, пункты меню) ссылаются на иконки по имени токена в `.style`-файлах, а не по прямому пути к файлу. Например, кнопка отправки сообщения описана так:

```
historySendIcon: icon {{ "chat/input_send", historySendIconFg }};
```

Значит, сама картинка лежит в `telegram_fork/tdesktop/Telegram/Resources/icons/chat/input_send.png` (и `@2x`/`@3x` рядом). Чтобы найти нужный токен, ищите текст на кнопке/пункте меню прямо по исходникам:

```
grep -rn "Photo or Video" telegram_fork/tdesktop/Telegram/SourceFiles
```

это выведет файл, где определён пункт меню, а рядом в коде обычно виден стиль/иконка, которую он использует. Дальше ищем сам токен в `.style`-файлах:

```
grep -rn "menuIconPhoto\b" telegram_fork/tdesktop/Telegram/SourceFiles --include="*.style"
```

**Способ 2: искать файл напрямую по названию.** Если понятно, как иконка должна называться по-английски (`search`, `delete`, `lock`, `play`, `pause`), можно просто поискать файл:

```
find telegram_fork/tdesktop/Telegram/Resources/icons -iname "*search*" | grep "@3x"
```

Так находится список кандидатов, дальше их нужно открыть и посмотреть глазами, какой действительно похож на то, что видно в официальном приложении.

### Обязательно проверяйте картинку глазами перед использованием

В `Resources/icons` лежат сотни файлов с похожими именами (`media_play`, `player_play`, `player_play_big`, `overview_video_play` и так далее) — для разных контекстов используются разные варианты. Перед тем как копировать файл в проект, откройте его и посмотрите, подходит ли форма. В этой сессии, например, для кнопки паузы записи голосового сообщения был выбран `media_pause@3x.png`, а не `player_pause@3x.png` — потому что первый по силуэту ближе к тому, что использует реальный composer, а не аудиоплеер.

## Как встроить иконку в проект

Три шага, полностью руками, без всякой генерации кода.

### 1. Скопировать файл

```
cp telegram_fork/tdesktop/Telegram/Resources/icons/chat/input_send@3x.png resources/icons/send.png
```

Файл переименовывается в короткое имя без `@3x` — масштаб в имени файла проекту не нужен, потому что PNG используется только как источник для перекраски и масштабирования в рантайме, а не показывается напрямую в трёх разных размерах.

### 2. Добавить в resources.qrc

Открыть `src/ui/qt/resources.qrc` и добавить строку внутри `<qresource>`:

```xml
<file alias="icons/send.png">../../../resources/icons/send.png</file>
```

`alias` — это путь, по которому файл будет доступен в коде через `:/icons/send.png` (двоеточие в начале — синтаксис Qt resource path, не опечатка). Путь `../../../resources/icons/send.png` — потому что `resources.qrc` лежит в `src/ui/qt/`, а сама папка `resources/` — в корне репозитория, три уровня вверх.

Пересборка автоматически подхватит новый `.qrc`-список файлов (`CMAKE_AUTORCC` уже включён в `CMakeLists.txt` для Qt-сборки) — отдельной команды генерации запускать не нужно, обычная сборка (`cmake --build build` или `build.ps1`) сама всё найдёт.

### 3. Подключить в icons.cpp

Добавить новое значение в `enum class Glyph` (`src/ui/qt/icons.hpp`) с комментарием, откуда взята картинка:

```cpp
enum class Glyph {
    ...
    NewThing,  // chat/new_thing_icon - для чего используется
};
```

И добавить путь к ресурсу в `glyphResourcePath()` (`src/ui/qt/icons.cpp`):

```cpp
case Glyph::NewThing:
    return ":/icons/new_thing.png";
```

Всё остальное (загрузка, кэширование, перекраска под цвет, масштабирование под размер кнопки) уже реализовано один раз в `paintGlyph()`/`glyphIcon()`/`glyphPixmap()` и работает для любого `Glyph` одинаково — новый код писать не нужно, только добавить строку в enum и в `switch`.

## Как работает перекраска под тему (для понимания, не для копирования руками)

Важно: исходные PNG из `Resources/icons/` — это НЕ готовые альфа-маски, при попытке использовать их напрямую они дают сплошные квадратики вместо иконок (это реально случилось и было исправлено, см. историю коммитов). Проверено напрямую через Python/Pillow: у этих файлов белая фигура нарисована на полностью непрозрачном чёрном фоне (альфа = 255 везде, у части файлов вообще нет альфа-канала). Настоящий tdesktop конвертирует эти файлы-исходники в реальную альфа-маску на этапе своей сборки (отдельный codegen-скрипт вне `lib_ui`, недоступен для копирования), поэтому zkgram делает эту конвертацию сам, в рантайме, при первой загрузке иконки.

`colorizeMask()` в `icons.cpp`:

1. Переводит картинку в `QImage::Format_ARGB32`.
2. Для каждого пикселя берёт его яркость (`qGray()`) и использует её как альфа-канал нового пикселя: белое (255) — непрозрачно, чёрное (0) — прозрачно, серое на границах фигуры — частично прозрачно (сохраняет сглаживание).
3. RGB нового пикселя — это всегда нужный цвет (серый для обычного состояния, синий для акцентного и так далее), альфа берётся из яркости исходника.

Результат — силуэт из PNG, залитый произвольным цветом, с сохранением сглаженных краёв. Один и тот же файл `send.png` таким образом красится и в серый, и в синий, без хранения отдельной картинки под каждый цвет.

## Как изменить размер иконки

Размер иконки НЕ зависит от разрешения исходного PNG-файла — `paintGlyph()` всегда масштабирует картинку под размер, который у неё запросили (с сохранением пропорций, по центру). Реальный видимый размер иконки определяется тем, КТО её рисует, а не самим `icons.cpp`.

**Иконка на кнопке (`QPushButton`/`RippleButton`, самый частый случай).** По умолчанию Qt использует свой собственный маленький размер иконки для кнопки (обычно около 16 пикселей, из `PM_ButtonIconSize` текущего стиля) — это НЕ зависит от размера самой кнопки и часто выглядит слишком мелко внутри крупной кнопки. Чтобы задать размер явно, сразу после создания кнопки:

```cpp
sendFileButton_ = new RippleButton(glyphIcon(Glyph::Attach, kIconFg), QString(), inputRow);
sendFileButton_->setIconSize(QSize(24, 24));
```

`setIconSize()` — свойство самой кнопки, не иконки, поэтому его достаточно задать один раз при создании: даже если иконка на кнопке потом меняется через `setIcon(...)` (как у кнопки микрофона/отправки, которая переключается между `Glyph::Mic` и `Glyph::Send`), размер остаётся прежним.

**Иконка внутри поля ввода** (`QLineEdit::addAction(...)`, например поле поиска) — своего простого способа задать размер нет, Qt сам решает по внутреннему стилю `QLineEdit`. Не настраивалось, крупная переделка при необходимости.

**Иконка через `paintGlyph()`/`glyphPixmap()` напрямую** (не через `QIcon`, а там, где иконка рисуется вручную в `paintEvent`, например пузыри сообщений) — размер это буквально прямоугольник (`QRectF rect`/параметр `size`), который передаётся при вызове. Увеличить — значит передать больший `rect`/`size` в месте вызова.

## Что здесь не автоматизировано и почему

- **Нет скрипта, который сам находит и копирует иконки.** Подбор правильного файла требует посмотреть картинку глазами и сверить с тем, что реально показывает официальный клиент — это осознанно ручной шаг, не подходящий для слепой автоматизации (легко случайно взять `player_play` вместо `media_play` просто по совпадению первых букв в имени).
- **Нет анимированных (Lottie) иконок.** Настоящий tdesktop для морфинга "микрофон превращается в стрелку отправки" использует Lottie-анимацию (`Ui::Controls::SendButton::paintLottieIcon`, `telegram_fork/tdesktop/Telegram/SourceFiles/ui/controls/send_button.cpp`), а не статичную картинку. В zkgram это по-прежнему два отдельных статичных состояния (иконка микрофона, иконка отправки), переключаемых мгновенно, без плавной анимации превращения одной в другую — воспроизводить полноценный Lottie-плеер ради одной кнопки не стали, это отдельная, гораздо более крупная задача.
